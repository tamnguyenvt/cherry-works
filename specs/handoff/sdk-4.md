## Decisions

- User selected SDK Story 4 on 2026-11-03.
- Accepted at the spec gate:
  - The last release's contract is `packages/engine/contract.d.ts`, a copy of the built `index.d.ts` that each release commit records; none means the engine was never released, and nothing is compared. Older contracts are read from their tags (`git show v<version>:packages/engine/contract.d.ts`).
  - Asked by the user: the copy opens with a line saying it is generated by `pnpm release` and must not be edited.
  - Compared per top-level declaration and per exported name, comments and whitespace aside: one removed or changed is a breaking change, one new is an addition. Every change counts as breaking, since whether a tool implements or receives a type cannot be told.
  - Breaking changes without a new major are refused, naming each declaration; additions in a patch are refused; a version below 1.0.0 is refused.
  - A major with breaking changes is refused unless its `## <version>` section of `CHANGELOG.md` names each broken declaration.
  - The engine tarball is checked like `cw`'s: not yet published, packed, installed apart, `VERSION` read back; each refusal names its package. Both are packed before anything is recorded; `cw` is published, then the engine with `--access public`.
  - The file-adapter duties in the README are prose and are not compared; confirmed by the user at the hand-over, and written into SDK-FR-015.
