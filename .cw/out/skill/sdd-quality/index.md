The quality pass. It reads and runs, and fixes nothing.

1. **Checklist** — `<spec folder>/quality.md` (`.sdd/settings.json`). Where
   there is none, write it first: the body of [sdd-quality-doc](../../template/sdd-quality-doc/index.md), from
   `# Quality` on, without its closing `Generated by` comment.
2. **Gather** — read `spec.md`, every `spec-<key>.md` and `plan.json`; find
   the code each story runs through with [sdd-locator](../../agent/sdd-locator/index.md). Run `check` of
   [sdd-specs](../../script/sdd-specs/index.md) and /sdd-analyze; run every test and static check the
   project defines twice, the way the baseline does. A failure a handoff note
   records as known is still a violation, named as known.
3. **Check** — each item of the checklist, across the whole codebase and
   every spec: `pass`, or `fail` with each violation, citing the stories, FR
   or SC behind it, and `path:line` where it is in the code. A spec with no
   `Done` story is checked against the other specs, and no code against it.
4. **Grade** the product once, from the items: A every one passes; B only
   warnings; C one violation; D two or more; F a check fails, or a `Done`
   scenario nothing proves.
5. **Report** — under `## Last pass` at the end of `quality.md`, in place of
   the one there, the checklist above it left as it is: the date, the
   cross-check story that ran it or "on request", each item with its result
   and violations, and the grade.
6. **Plan the fixes** — hand the violations to /sdd-plan, which writes the
   stories that fix them, for the user to accept. A pass that finds none says
   so.
